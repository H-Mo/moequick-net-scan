## 1. 计划原则

1. **每阶段必须可运行**：每个阶段结束时都能编译出 `MQNetScan.exe` 并让用户点得动，不允许出现“只提交代码、跑不起来”的阶段。
2. **验收权在用户**：每阶段交付「可运行 exe + 该阶段验收清单 + 自测结果」，由用户在真机勾选；清单未全绿不进入下一阶段。
3. **优先切掉不可控依赖**：把“状态机+队列”与“真实网络探测”拆成两个阶段（S4 / S5），让最容易写错的并发逻辑在**无网络依赖**的前提下先验收。
4. **先保证体感，再堆功能**：`ListView` 刷新（S6）排在端口扫描（S7）之前，先确认“不卡”这条最影响评价的能力。
5. **不赶工期**：已确认采用“不着急、尽可能细化拆分”的口径，因此阶段粒度偏细（14 个阶段），每个阶段工作量控制在「1 次验收能看完」的规模。
6. **阶段内返工免费，阶段后新需求排队**：验收通过后追加的需求记入 `doc/backlog.md`，不打断当前阶段。

| `NetSegmentTests` | 单测覆盖 |

**验收清单（S2）**
- [ ] 装了 VMware/VirtualBox 的机器上，下拉框只出现物理网卡

- [ ] 输入 `/22` → 目标数 1022；输入 `/31`、`/32`、`/7` → 明确拒绝并说明原因

- [ ] 单测：网段计算在 `/8`、`/24`、`/30` 三个边界值上数值正确

**完成定义**：以上全绿；`NetSegmentTests` 通过。

### S4 — 调度核心（假数据驱动，不碰网络）

> **本阶段不写任何 Socket/SendARP 代码。** 用假数据灌入，把并发调度与暂停/终止语义先验收干净。

| 交付物 | 说明 |
| --- | --- |
| `AddressQueue` | 自建阻塞队列（`Monitor.Wait/Pulse`），支持 `PulseAll` |
| `ScanStateMachine` | Idle/Running/Paused/Stopped/Completed，非法迁移抛异常 |
| `ScanSession` | 一次性实例，持有参数快照 + 工作线程数组 |
| `ProgressTracker` | `Interlocked` 计数、暂停累计耗时 |
| `ResultQueue` + `IResultSink` | 结果投递通道 |
| **临时假探测器** | 每 IP 随机 `Thread.Sleep(20~80ms)` 后返回一条伪造 `HostRecord`（S5 删除） |

**验收清单（S4）**
- [ ] 254 条假数据：进度条单调递增，不回退
- [ ] 点“暂停” → 1 秒内不再有新结果进入；点“继续” → 从断点续，已完成不重复
- [ ] 点“终止” → 2 秒内停止，已产生的结果保留，状态栏显示“已终止（部分结果）”
- [ ] 连续 20 次“开始→终止”：无线程堆积（任务管理器线程数回落）、无异常弹窗
- [ ] 扫描期间窗口可拖动、可切 Tab、标题栏无“未响应”
- [ ] 单测：`Completed → Paused` 等非法迁移被拒绝
- [ ] 单测：队列在“空队列 + 终止唤醒”下无死锁

**完成定义**：以上全绿；`StateMachineTests`、`AddressQueueTests` 通过。**这是全项目风险最高的阶段，不达标不进入 S5。**

### S5 — ARP 存活探测（真实网络）

| 交付物 | 说明 |
| --- | --- |
| `NativeMethods.SendARP` + `NativeStructs` | 唯一 `DllImport` 文件 |
| 字节序处理 | 点分 IP → **小端** `uint`（`BitConverter.ToUInt32`）；单测锁定。**注意：v1.0 曾误写为大端，已实测修正，见 architecture §4.1.1** |
| 无效 MAC 过滤 | 全 `FF` / 全 `00` 不判存活 |
| 信号量限流 | `min(并发, 16)` 硬上限 |
| 重试 | `SendArpRetry` 次，间隔 50ms |
| 接入 S4 调度 | 假探测器删除，改真实 ARP |
| `ArpByteOrderTests` | 单测 |

**验收清单（S5）**
- [ ] 单测：`192.168.1.1` 经小端转换结果应为 `0x0101A8C0`（**若得 `0xC0A80101` 说明用了大端，必然全部探测失败**）
- [ ] 真机扫描默认 /24：结果与 `arp -a` 中同网段条目**一致**（允许毫秒级时序差异导致的个别增减）
- [ ] 目标机开启防火墙“禁止 Ping”后，仍能被发现
- [ ] 空网段扫描：列表为空，状态栏“存活 0 台”，**不出现任何离线设备占位行**
- [ ] 并发设为 128 时，同时刻 ARP 调用数仍不超过 32（可用日志或调试计数验证）
- [ ] 扫描期间进度条持续推进，**不显示耗时预估**（用户决策：只做进度条）
- [ ] 扫描中断网线：不崩溃，以“部分失败”结束并给出原因

**完成定义**：以上全绿。**若字节序有误，会表现为“全部探测失败但 arp -a 明明有条目”，必须在此阶段排除。**

### S7 — 端口探测与角色判定

| 交付物 | 说明 |
| --- | --- |
| `PortProber` | 非阻塞 `Connect` + `Socket.Select`，单 IP 总预算 = 超时×2 |
| `WSAEWOULDBLOCK` 处理 | 连接进行中不当作错误 |
| `ErrorClassifier` | 拒绝/超时/不可达 分类 |
| `RoleResolver` | 内置优先级；`RoleResolverTests` |
| 接入调度 | 端口结果与 ARP 结果合并为完整 `HostRecord` |

**验收清单（S7）**
- [ ] 目标机 `netstat -an` 列出的监听端口，与工具探测结果**一致**
- [ ] 同一台开 1433+445 的主机 → 角色显示“本地服务器”（优先级生效）
- [ ] 全部规则端口关闭的主机 → 角色“未知”
- [ ] 黑洞 IP（不可达但 ARP 有回应）→ 在预算内结束，不拖住整个队列
- [ ] 并发 32 与 128 各扫一次 /24：两种设置下结果集一致
- [ ] 单测：`RoleResolver` 覆盖 5 个内置角色 + 多角色同时命中的优先级
- [ ] 句柄观察：20 轮扫描后 Handle 数回落

**完成定义**：以上全绿；端口结果与 `netstat` 一致是本阶段硬门槛。

**验收清单（S11）**
- [ ] 普通权限点“清理 ARP” → 弹指引框（含命令与复制按钮），**全程无 UAC 弹窗**

- [ ] `ncpa.cpl`、`services.msc` 均能打开；权限不足时提示需管理员
- [ ] 单点测通：分别构造 ① 开放端口 ② 拒绝端口 ③ 黑洞 IP ④ 不存在的域名，四种结果文案不同
- [ ] 单点测通黑洞 IP 时 UI 不卡（≤5 秒强制结束）

- [ ] 自检界面明示“当前自检域名：xxx”

**完成定义**：以上全绿。**“普通权限不弹 UAC”是本阶段最高优先级验收项。**

## 6. 变更与返工规则

| 情形 | 处理 |
| --- | --- |
