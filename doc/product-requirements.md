## 1. 背景与目标

### 1.1 背景

局域网运维长期依赖“逐台机器手工排查”：拔插网线、逐台 ping、开远程桌面、查看路由器后台。典型故障现场的共性问题：

1. **部分电脑和打印机常禁 Ping**，`ping` 扫不到设备，运维误判为“设备掉线”，浪费大量时间。
2. 局域网内设备类型多样（打印机、电子秤、安卓设备、本地 SQL Server、旧版 Windows 电脑），**没有一张“谁是谁”的现场拓扑图**。
3. 运维工具本身要么需要安装（装不上、装不上就装全家桶）、要么依赖 .NET 4.5+ / 第三方 DLL，在 **Win7 SP1 等旧版 Windows 电脑**上直接起不来。
4. 排查结论只在口头传递，**没有可交付的现场凭证**，返工时无法复盘。

### 1.2 产品目标

提供一个**零安装、零依赖、单文件、普通权限即可启动**的 Windows 桌面工具，让运维人员在 3 分钟内回答四个问题：

- 这个网段里**活着哪些设备**？（可选择 ARP 或 ICMP Ping）
- 每台设备**是什么角色**？（打印机 / 电子秤 / Windows 电脑 / 本地服务器 / 安卓设备）
- 网络本身**有没有问题**？（网关是否可达、是否 IP 冲突、DNS/外网是否通）
- 排查结果**能不能直接交付**？（可导出的纯文本诊断报告）

### 1.3 非目标（明确不做）

- 不做端口漏洞扫描 / 弱口令爆破 / 任何攻击性探测。
- 不做跨网段路由追踪、不做 SNMP 采集、不做设备配置下发。
- 不做后台常驻服务、不做开机自启、不做数据上报。
- 不提供安装包、不写注册表、不写系统目录。

## 2. 目标用户与使用场景

| 角色 | 使用频率 | 关注点 | 关键诉求 |
| --- | --- | --- | --- |
| 局域网运维工程师 | 每天多次 | 快速定位“哪台设备掉了” | 一键扫网段、结果可读、能复制 IP/MAC |
| IT 技术支持（电话远程指导） | 每天多次 | 协助现场人员完成基础排查 | 界面易读、错误提示清晰、结果便于传递 |
| 现场操作人员 | 故障时使用 | 点开始、导出并分享报告 | 不需要理解 ARP/端口概念 |
| 网络实施人员 | 部署或变更时 | 核对设备清单、保存网络现状 | 角色判定准确、报告可作为交付记录 |

### 2.1 典型场景（验收须覆盖）

1. **场景 A｜打印机“掉线”**：现场人员发现打印机无法打印。运维打开工具，扫描所在网段；若打印机 IP 存在但 9100 端口未开放，可判定打印服务异常，并尝试打开 Web 后台。
2. **场景 B｜网络设备盘点**：实施人员扫描局域网并导出报告，核对打印机、电子秤、Windows 电脑、服务器等设备是否齐全。
3. **场景 C｜网关故障**：工具顶部红色预警“默认网关不可达”，运维优先检查交换机、路由器或上联线路。
4. **场景 D｜IP 冲突**：不同设备以不同 MAC 回应同一 IP 的 ARP 请求 → 顶部红色预警“检测到 IP 冲突”，并指明冲突 IP。
5. **场景 E｜旧版 Windows 兼容**：在 Win7 SP1、2GB 内存等较旧的 Windows 电脑上，双击 exe 直接运行，无 UAC 弹窗、无“缺少 .NET Framework”报错。

## 3. 术语表

| 术语 | 说明 |
| --- | --- |
| SendARP | `iphlpapi.dll` 导出的 ARP 请求 API，用于二层同网段探测，**不受目标禁 Ping 影响** |
| ICMP Ping | Windows `Ping` API 的 Echo 探测，可用于路由可达的目标网段；目标或网络禁 ICMP 时可能漏报 |
| 探测方式 | 用户可在扫描目标中选择 ARP 或 Ping；ARP 可获取 MAC，Ping 成功主机的 MAC 列为空 |
| 存活主机 | ARP 模式下为得到有效 MAC 回应的主机；Ping 模式下为得到 ICMP Echo 成功回应的主机 |
| 角色 | 根据开放端口命中“端口特征规则表”推导出的设备类型标签 |
| 深度测速 | 对指定 IP:端口连续建立 3 次 TCP 连接，统计耗时分布的测量动作 |
| IP 冲突 | 同一 IP 在短时间内回应了不同 MAC，或 ARP 回应 MAC 与本机 ARP 表记录不一致 |
| 提权 | 以管理员身份重新启动进程（仅用于 ARP 缓存清理的引导，不自动执行） |

## 4. 范围与约束基线

### 4.1 运行环境（硬性红线，不可协商）

| 项 | 约束 |
| --- | --- |
| 运行时 | `.NET Framework 4.0`（`v4.0`），**不得**要求 4.5 / 4.6 / 4.8 |
| UI 框架 | WinForms（`System.Windows.Forms`） |
| 目标系统 | Windows 7 SP1 及以上（32/64 位均可运行）；同时需在 Win10/Win11 正常使用 |
| 语言特性 | **禁止** `async/await`、`Task.Run`、`Task`/`Task<T>`、`HttpClient`、`CallerMemberName`、`IReadOnlyList` 等 4.5+ 专属 API |
| 第三方依赖 | **零** NuGet 包、零外部 DLL，仅使用 GAC 内系统程序集 |
| 部署形态 | 单文件 exe，纯绿色免安装，可放 U 盘直接运行 |
| 配置文件 | 与 exe **同级目录**的 `MQNetScan.ini` |
| 权限 | 清单声明 `requestedExecutionLevel level="asInvoker"`，默认不弹 UAC |
| 架构 | 建议 `AnyCPU`（走 32 位进程亦可，二者均须在 64 位系统可用） |

### 4.2 明确排除项

- 不支持跨网段/跨 VLAN 的直接 ARP 探测（受 ARP 协议本身限制，非缺陷，见 §9.2）。
- 不保证对开启“端口敲门/ARP 防护”的设备给出正确角色判定。
- 不做 IPv6 探测。
- 不缓存历史扫描结果（每次启动为空白会话）。

## 6. FR-1 局域网探测（Tab 1）

### 6.1 FR-1.1 网卡枚举与网段确定

**描述**：启动后自动枚举本机所有**活动物理网卡**上的 IPv4 单播地址，供用户选择扫描源。

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| FR-1.1.1 | 通过 `NetworkInterface` 枚举 `OperationalStatus == Up` 且 `NetworkInterfaceType` 为 Ethernet / Wireless80211 / 以太网/无线等物理类型的网卡 | 虚拟网卡（VMware / VirtualBox / Hyper-V / VPN / Loopback / Tunnel）不出现在列表中 |
| FR-1.1.2 | 列表显示“网卡描述 + IPv4 地址 + 子网掩码 + 前缀长度”，并标明默认网关是否配置 | 若系统有多块活动网卡，默认选中**带默认网关**的那一块 |
| FR-1.1.3 | 根据所选网卡计算 CIDR 网段（如 `192.168.1.0/24`），默认只扫描该网段内的**可用主机地址**（排除网络号与广播地址） | 选中 `192.168.1.10/24` 时，默认目标数为 254 |
| FR-1.1.4 | 允许用户手动输入自定义网段（CIDR 形式，如 `10.1.0.0/22`）或起止 IP 区间 | 非法输入即时校验并给出具体原因（如“掩码长度需在 8~30 之间”） |
| FR-1.1.5 | 目标地址数大于 254（/24）时，**开始扫描前必须弹出确认框**，展示“目标数量 + 经验耗时提示”，由用户决定是否继续 | 输入 `/22`（1022 个地址）时确认框必现；取消后不产生任何扫描活动 |
| FR-1.1.6 | 无任何活动物理网卡时，界面给出明确提示并禁用“开始扫描”，但 Tab 2/Tab 3 仍可用 | 拔掉网线启动程序，不出现异常崩溃或空白表 |
| FR-1.1.7 | 本机自身 IP 不进入结果列表（但参与网关/冲突检测） | 扫描结果中不含本机地址 |

### 6.2 FR-1.2 存活探测（SendARP）

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| FR-1.2.1 | 对每个目标地址调用 `SendARP`（P/Invoke `iphlpapi.dll`）进行二层探测，**不依赖 ICMP** | 目标防火墙开启“禁止 Ping 响应”时仍能被发现 |
| FR-1.2.2 | 仅将 **SendARP 返回有效 MAC** 的地址判定为存活并加入结果表；无 MAC 回应的地址**不进入列表** | 空网段扫描后结果表为空，且状态栏正确显示“存活 0 台” |
| FR-1.2.3 | 存活主机记录：IP、MAC（大写、冒号分段）、MAC 前 3 字节作为厂商前缀展示 | 与 `arp -a` 结果一致（允许毫秒级时序差异） |
| FR-1.2.4 | 产品假定“现场设备均为可探测设备”，**不提供离线/无响应设备清单，也不做离线告警** | 报告中不含“离线设备”章节 |

> 归一化说明：原讨论中的“离线主机灰色标注”已取消。列表只呈现已确认存活的主机，扫描覆盖面通过状态栏与报告的统计行体现（见 FR-1.7）。

### 6.3 FR-1.3 并发特征端口扫描

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| FR-1.3.1 | 对每台存活主机，按其 IP 并发发起**特征端口 TCP 连接**，端口集合来自 Tab 3 的规则表（内置默认见 §6.7） | 关闭全部规则端口后扫描，角色显示“未知” |
| FR-1.3.2 | 并发度与单端口超时时间取自 Tab 3 设置（并发 16~128，默认 32；超时默认 800ms，可调） | 修改设置后立即对下一次扫描生效，无需重启 |
| FR-1.3.3 | 连接成功（`TcpClient.Connect` 成功或 `Socket` 连接完成）即记为“开放”；超时/拒绝记为“关闭” | 与目标机本地 `netstat -an` 监听状态一致 |
| FR-1.3.4 | 多点握手采用**非阻塞 connect + `Socket.Select` 轮询**（禁止每端口起线程/`Task`），单次连接超时严格可控 | 扫描 254 地址 × 12 端口期间，UI 线程不出现持续卡顿 |
| FR-1.3.5 | 扫描为**可中断、可暂停、可继续**的长任务，全部工作在线程池之外的独立后台线程中执行，UI 通过 `Timer` 轮询刷新 | 见 FR-1.4 |

### 6.4 FR-1.4 进度、暂停/继续、终止

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| FR-1.4.1 | 提供“开始扫描 / 暂停 / 继续 / 终止”四个操作，按钮可用态随状态机切换 | 未扫描时仅“开始”可用；扫描中“开始”禁用 |
| FR-1.4.2 | 进度条显示整体完成百分比；状态栏显示“已探测 X/Y 地址｜存活 N 台｜已用时长” | 数值单调递增，不出现回退 |
| FR-1.4.3 | 暂停时立即停止发起新的探测任务，已在途连接允许自然结束（≤ 单个超时时长）；继续时从断点续扫 | 暂停 10 秒后继续，已完成部分不重复扫描 |
| FR-1.4.4 | 终止时尽快（≤ 2 秒）停止所有探测、清理资源，保留已获得的结果，状态栏标记“已终止（部分结果）” | 终止后可立即重新开始新一轮扫描 |
| FR-1.4.5 | 扫描期间窗口可自由拖动、最小化、切换 Tab | 不出现“未响应”标题栏 |
| FR-1.4.6 | 结果表采用**增量刷新**：每发现一台存活主机即插入一行，不等待全部完成 | 扫描开始数秒内即可看到前几台设备 |

### 6.5 FR-1.5 顶部红色预警区

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| FR-1.5.1 | 扫描开始前（或启动时）检测默认网关连通性（ARP + 一次 TCP 探测 80/443 任一，或 ICMP 兜底）；不可达则显示红色横幅 | 拔掉上行链路时必现红色预警 |
| FR-1.5.2 | 检测 IP 冲突：同一 IP 在扫描窗口内返回不同 MAC，或与扫描前本机 ARP 表记录不一致 | 手工构造冲突（两台机同 IP）时可复现告警并给出冲突 IP |
| FR-1.5.3 | 红色预警内容为“结论 + 一句话建议”，可关闭（X），但同一问题再次出现时会重新显示 | 点击关闭后横幅隐藏，不影响扫描继续 |
| FR-1.5.4 | 正常状态时预警区**完全不占位**（不显示空白条） | 布局不出现多余留白 |

### 6.6 FR-1.6 结果表与右键菜单

**表格列**（固定顺序）：

| 列 | 说明 |
| --- | --- |
| # | 行号（从 1 递增） |
| IP 地址 | 存活主机 IPv4 |
| MAC 地址 | 大写冒号分段 |
| 厂商前缀 | MAC 前 3 字节（OUI），如 `00:1B:A9` |
| 开放端口 | 逗号分隔，如 `9100, 515, 631` |
| 设备类别 | 按 §7 端口/协议证据规则判定 |
| 可信度 | 高 / 中 / 低 / 未知；表示证据强度而非身份认证 |
| 识别依据 | 说明命中的端口、网关或协议证据 |
| 深度测速 | 仅在用户执行过右键“深度测速”后显示结果，否则为 `—` |

**交互硬约束**：

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| FR-1.6.1 | **列表严禁双击触发任何外部动作**（不得打开浏览器、不得启动 mstsc、不得复制） | 双击任意行/单元格无任何副作用 |
| FR-1.6.2 | 所有快捷操作**仅**通过右键菜单提供 | 菜单项见下表 |
| FR-1.6.3 | 右键菜单在未选中行时禁用全部操作项 | 空白处右键 → 菜单项灰化 |
| FR-1.6.4 | 支持排序（点击列头）、多选行、`Ctrl+C` 复制选中行（制表符分隔，便于贴入 Excel） | 粘贴到记事本内容对齐 |

**右键菜单项**：

| 菜单项 | 行为 | 失败时的提示 |
| --- | --- | --- |
| 复制 IP 地址 | 写入剪贴板 | 无 |
| 复制 MAC 地址 | 写入剪贴板 | 无 |
| 复制整行（IP + MAC + 端口 + 角色） | 写入剪贴板 | 无 |
| 深度测速（3 次握手） | 对该 IP 的首个开放端口（无开放端口则用 3389→445→80 顺序挑第一个可连端口）建立 3 次 TCP 连接，显示 3 次耗时与平均值 | 全部失败时提示“3 次连接均失败，目标端口不可达” |
| 浏览器打开 Web 后台 | 用默认浏览器打开 `http://<IP>`（若命中 8080/8443 等则带上端口），**禁止**在程序内嵌 WebView | 无默认浏览器时提示手动复制地址 |
| 打开远程桌面（mstsc） | 以 `mstsc /v:<IP>` 启动系统远程桌面 | 目标 3389 未开放时先提示“该主机 3389 未开放，仍要尝试连接吗？” |
| 单点测通（跳转 Tab 2） | 将该 IP 与首个开放端口带入 Tab 2 的握手测通器 | 无 |

> 深度测速与 mstsc 的外部进程启动必须捕获异常，任何失败都只能弹提示，**不得让主程序退出**。

### 6.7 FR-1.7 导出纯文本诊断报告

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| FR-1.7.1 | 提供“导出报告”按钮，生成**单个 `.txt` 文件**（UTF-8 带 BOM，保证记事本打开中文不乱码） | Win7 记事本打开无乱码 |
| FR-1.7.2 | 文件名含时间戳：`MQNetScan_报告_yyyyMMdd_HHmmss.txt` | 连续导出两次不覆盖 |
| FR-1.7.3 | 默认保存位置为**桌面**；若桌面不可写则回退到 exe 同级目录；用户可在保存对话框中另存 | 桌面无写权限时仍能成功导出 |
| FR-1.7.4 | 报告含四段：① 表头信息 ② 逐台明细 ③ 异常告警 ④ 结论与建议 | 段落顺序固定 |
| FR-1.7.5 | 导出成功后提示文件完整路径，并提供“打开所在文件夹”入口 | 提示中的路径可直接定位到文件 |
| FR-1.7.6 | 结果为空时允许导出，报告中明细段写“本次扫描未发现存活设备” | 不生成 0 字节文件 |

**报告模板（固定骨架）**：

## 7. FR-2 设备角色判定规则

### 7.1 内置端口特征规则表

| 角色 | 默认特征端口 | 说明 |
| --- | --- | --- |
| 打印机 | 9100, 515, 631 | RAW / LPR / IPP |
| 电子秤 | 4001, 5000, 8000, 3000 | 主流计价秤/条码秤通讯端口 |
| 本地服务器 | 1433 | SQL Server |
| Windows 电脑 | 445, 3389, 135 | SMB / RDP / RPC |
| 安卓设备 | 5555 | ADB |

### 7.2 判定优先级（**内置固定，不可修改**）

`本地服务器 > Windows 电脑 > 打印机 > 电子秤 > 安卓设备 > 网络设备（仅 80/443）> 未知`

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| FR-2.1 | 一台主机命中多个角色时，按上述优先级取**唯一**角色展示 | 同时开放 1433 与 445 的主机显示“本地服务器” |
| FR-2.2 | 无任何规则端口开放的主机显示“未知” | 空白列不出现空字符串 |
| FR-2.3 | 角色名称固定，不因设置变更而改变（设置页只能增删改**端口与角色**的映射条目，不能改优先级顺序） | 设置页无优先级拖拽/排序控件 |
| FR-2.4 | 同一角色命中多个端口时，开放端口列按端口号升序列出全部开放端口 | 不截断、不合并 |

### 7.3 设备识别可信度与证据

角色类别只表达网络侧可观察到的线索，不等同于设备身份认证。主机记录包含可信度与识别依据：

| 可信度 | 含义 |
| --- | --- |
| 高 | 命中较明确的端口/协议特征；仍不能证明业务用途 |
| 中 | 命中单一服务或设备通讯端口，存在其它设备复用可能 |
| 低 | 通用端口或厂商信息等弱线索 |
| 未知 | 没有命中特征规则 |

当前端口规则可辅助识别 Windows 电脑、安卓设备、打印机、电子秤和本地服务器。80/443 只作为网络设备的低可信线索。iPhone/iPad、电视、空调等类别须有 SSDP、mDNS 或明确厂商协议证据；在协议探测实现前不得仅凭 OUI 或 Ping 自动作出确定分类。

### 7.4 角色显示与配色

- 角色列文本左对齐，不同角色使用不同单元格底色（低饱和度，保证 Win7 基本主题下可读）。
- 颜色仅为辅助信息，**不作为验收依据**；文字必须能独立表达含义（色弱可用）。

## 11. 非功能需求

### 11.1 兼容性（最高优先级）

| 编号 | 需求 |
| --- | --- |
| NFR-C1 | 在 Windows 7 SP1（32 位，仅装 .NET 4.0）上可启动、可扫描、可导出 |
| NFR-C2 | 在 Windows 10/11 上功能无缺省、无兼容性提示弹窗 |
| NFR-C3 | 全部 P/Invoke 声明需显式 `CharSet`/`CallingConvention`，避免 32/64 位结构体对齐差异 |
| NFR-C4 | 不依赖 WMI 服务（旧版 Windows 电脑上的 WMI 可能不可用），网卡信息优先走 `NetworkInterface` |

### 11.2 稳定性

| 编号 | 需求 |
| --- | --- |
| NFR-S1 | 连续执行 20 次“开始→终止”循环，不出现句柄泄漏、内存持续增长或崩溃 |
| NFR-S2 | 扫描大网段（/16，65534 地址）时若用户终止，进程内存不持续膨胀（结果表设行数上限 5000 行，超出后仍统计但不追加显示） |
| NFR-S3 | 网络中途断开（拔网线）不导致崩溃，扫描以“部分失败”结束并给出原因 |
| NFR-S4 | 所有后台线程为前台线程或显式守候，进程退出时无残留线程阻塞关闭（关闭窗口 ≤ 3 秒内退出） |

### 11.3 性能（不作为硬性承诺）

- 不设定强制耗时指标（已确认采用宽松口径）。产品仅需保证：
  1. 扫描 254 地址默认参数下，进度条**每 2 秒内至少推进一次**，让用户感知到在工作；
  2. 开始前对 >254 地址的目标给出经验耗时提示（如“约 2~5 分钟”），措辞为**预估**而非承诺；
  3. UI 在任何规模扫描下均保持可拖动、可暂停、可终止。

### 11.4 权限与安全

| 编号 | 需求 |
| --- | --- |
| NFR-P1 | 默认 `asInvoker`，启动不弹 UAC |
| NFR-P2 | 除 ARP 缓存清理外，所有功能在普通权限下可用；清 ARP 在非管理员时仅给出操作指引，**不自动弹 UAC** |
| NFR-P3 | 不写入注册表、不写系统目录、不创建计划任务、不联网上报 |
| NFR-P4 | 不记录任何密码/凭据；报告中不含本机用户名与计算机名以外的敏感信息（可配置脱敏） |
| NFR-P5 | 扫描仅做 TCP connect 与 ARP 请求，不发送任何应用层载荷（浏览器打开 Web 后台除外，由用户主动触发） |

### 11.5 可维护性

- 探测逻辑、角色判定、报告生成、配置读写各自独立，便于后续单独替换。
- 关键路径（SendARP 失败、socket 异常）需有统一的错误分类枚举，避免散落的中文字符串拼接。
- 保留轻量运行日志能力（可选，默认关闭；开启后写 exe 同级 `MQNetScan.log`，限制单文件 1MB 滚动）。

## 12. 风险与已知限制

| 编号 | 风险/限制 | 影响 | 应对 |
| --- | --- | --- | --- |
| R1 | ARP 仅在同网段有效；扫描跨网段（如 /16 中的其他子网）时，远端设备不会被发现 | 用户误以为“网段里没设备” | 界面对跨子网目标在确认框中提示“跨网段设备可能无法被 ARP 发现，建议逐段扫描” |
| R2 | 部分设备启用 ARP 防护/端口敲门，端口探测结果为“全关闭” | 角色误判为“未知” | 报告中“未知”设备数量高亮，并建议补充端口规则 |
| R3 | 旧电脑的 CPU/内存资源有限，128 并发可能引起系统整体卡顿 | 用户体验差 | 默认 32；并发设置在 **>64** 时给出“配置较低的电脑建议不超过 32”的提示 |
| R4 | 思迅 SaaS 域名默认值需实施确认，域名变更会导致自检误判 | 自检假阳性 | 域名放 ini 可配置，并在界面明示“当前自检域名：xxx” |
| R5 | Win7 无默认浏览器关联时“打开 Web 后台”失败 | 操作中断 | 捕获异常并提示手动复制地址 |
| R6 | `netsh` 在极少数精简系统被移除 | ARP 清理失败 | 回退 `arp -d *`，再失败则提示手工操作 |
