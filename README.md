# 萌快网维（MoeQuick NetScan）

面向 Windows 的局域网设备探测与运维辅助工具。无需安装，运行后可扫描局域网中的在线设备、查看开放端口、按端口特征辅助识别设备类别，并导出诊断报告。

> 本工具适用于一般局域网，不限于门店网络。它是现场排查辅助工具，不能替代网络管理员的判断，也不能保证识别出每一台设备。

## 下载与运行

1. 打开 [GitHub Releases](https://github.com/H-Mo/moequick-net-scan/releases) 下载 `MQNetScan-v1.4.0.zip`。
2. 将 ZIP 解压到你有写入权限的文件夹，例如桌面或“文档”。
3. 打开解压出的 `MQNetScan-v1.4.0` 文件夹，双击 `MQNetScan.exe` 运行。首次启动时，程序会在 exe 同一目录创建 `MQNetScan.ini`，用于保存设置。

ZIP 包内仅包含 `MQNetScan.exe` 和 `MQNetScan.exe.config`。无需安装，解压后双击程序即可运行；首次启动会在同目录生成 `MQNetScan.ini`。

软件面向 Windows 桌面系统，目标框架为 .NET Framework 4.0，设计目标包含 Windows 7 SP1 及更新版本。首次运行建议使用普通权限；清理 ARP 缓存等需要管理员权限的操作会先提供说明，不会自动弹出 UAC。

如果 Windows 显示安全提示，请先确认文件来自本项目的 Releases 页面，再按你所在组织的安全要求决定是否运行。

## 快速开始

### 扫描局域网

1. 打开“局域网探测”页，在网卡列表中选择当前正在使用的网络连接。
2. 选择 CIDR 网段或输入起止 IP。不了解 CIDR 时，可以先使用程序显示的默认网段；起止 IP 模式扫描的是你填写的精确范围。
3. 选择探测方式：ARP 适合同一广播域并能取得 MAC；Ping 适合路由可达的目标网段，但目标或网络屏蔽 ICMP 时可能漏报，且不会取得 MAC。程序会记住上次选择。
4. 点击“开始扫描”。范围较大时，程序会提示确认。扫描期间可以暂停、继续或终止。
5. 在结果列表中查看 IP、设备名称、MAC、厂商前缀、开放端口、设备类别和测速结果。设备名称通过反向 DNS 或 NetBIOS 尽力获取，获取不到显示“—”；Ping 模式下 MAC 和厂商前缀也显示“—”。
6. 需要留档时点击“导出诊断报告”。报告会优先保存到桌面；若桌面不可写，则尝试保存到程序目录。

选中设备后可使用右键菜单复制 IP、MAC 或整行信息，进行深度测速，打开设备 Web 管理页面或尝试远程桌面。远程桌面端口未检测到时，程序会先询问是否继续。

### 便捷功能

“便捷功能”页提供单端口连接测试、网络连接和服务管理器入口，以及网关、公共 DNS 和域名连通性自检。测试目标和结果会显示在页面中。

清理 ARP 缓存需要管理员权限。普通权限下，程序只展示手动操作说明和命令，不会自动请求提权。用户可以自行决定是否重新以管理员身份运行。

### 设置

“设置”页可调整扫描并发数、端口超时和设备角色的端口特征列表。程序会将配置保存在同目录的 `MQNetScan.ini` 中；备份或迁移设置时，可复制这个文件。

角色是根据端口特征作出的辅助分类。例如，445、3389 或 135 只能提供 Windows 电脑的线索，不能证明它是收银机或办公电脑；5555 也只能作为安卓设备的端口线索，不能证明设备一定是 POS；电子秤默认识别端口为 3001、4001、5001。可以按实际网络情况调整角色和端口，扫描结果仍需人工核实。

Ping 超时和尝试次数可在“设置”页调整；初始默认超时 800ms、尝试 1 次。设置保存在 `MQNetScan.ini` 的 `[Scan]` 配置中。旧版配置没有这些键时，会自动使用 ARP、800ms 和 1 次 Ping 尝试。

## 扫描结果的限制

- ARP 通常适合同一二层网络或广播域内的发现，可获取 MAC；跨网段时通常无法直接通过 ARP 发现目标，某些网关的代理 ARP 也可能影响结果。
- Ping 使用 ICMP Echo。目标必须路由可达且允许 ICMP；目标主机或防火墙屏蔽 Ping 时，即使设备在线也可能扫描不到。Ping 模式不会得到 MAC，因此 MAC、厂商前缀显示为“—”，也无法依赖 MAC 证据检测 IP 冲突或过滤网关代理 ARP。
- 设备名称依赖反向 DNS 或 NetBIOS；网络未配置名称记录、目标关闭 NetBIOS 或防火墙拦截时会显示“—”，这不代表设备离线。
- 设备或网络可能过滤 ARP、限制连接、屏蔽端口探测，或暂时离线。因此“未发现”不等于设备一定不存在，“端口未开放”也不等于设备故障。
- 开放端口只用于辅助判断设备类别，不是设备身份认证。多个类别可能共用端口，关闭端口也可能是防火墙策略所致。
- IP 冲突检测依赖扫描期间观测到的地址与 MAC 信息。若冲突设备没有响应，程序可能无法发现冲突。
- 网关、公共 DNS 和域名自检分别测试连接路径，不等同于完整的互联网或业务服务健康检查。
- 连通性自测默认使用阿里云域名 `www.aliyun.com`；该目标可在同目录 `MQNetScan.ini` 的 `[SelfCheck]` 配置中通过 `SaasDomain` 修改。
- 本程序不是端口漏洞扫描器，不会尝试登录设备、猜测密码、修改网络设备配置或上传扫描数据。

## 常见问题

### 扫描结果里没有网关或某台已知设备

先确认扫描电脑当前使用的网卡、IP、子网掩码和默认网关，再确认输入范围与设备处于同一局域网。可以在命令提示符运行 `ipconfig` 查看本机 IPv4 地址和默认网关。若设备位于不同 VLAN 或需要经路由器转发，ARP 扫描可能无法发现它。

### 扫描只发现本机或少数设备

可能是扫描范围填错、所选网卡不对、设备过滤 ARP，或者网络启用了客户端隔离。请用系统网络信息核对地址范围，并联系网络管理员确认 VLAN、无线客户端隔离和网关代理 ARP 设置。

### 某设备显示“未知”

“未知”表示当前开放端口没有命中已有角色规则，不代表设备一定异常。可在“设置”中按网络管理员提供的信息调整对应角色的端口特征；不要仅凭一个端口就断定设备用途。

### 为什么导出的报告不在桌面

程序会先尝试桌面；如果桌面不可写，则回退到程序所在目录。导出完成后，可以使用页面上的“打开所在文件夹”按钮定位报告。

### 为什么清理 ARP 或刷新 DNS 失败

Windows 可能要求管理员权限。请阅读程序给出的说明；只有在你确认需要且有权限时，再自行决定是否以管理员身份重新运行。程序不会在普通权限下自动弹出 UAC。

## 隐私与安全

扫描在本机执行。程序不会主动上传设备清单、IP/MAC 信息或诊断报告。报告保存在本机；分享报告前请检查其中是否包含不宜公开的网络地址、设备 MAC 或其他环境信息。

请仅扫描你拥有或获授权管理的网络，并遵守所在单位的网络安全规定。

## 开发者构建

本项目使用 C#、Windows Forms 和 .NET Framework 4.0，不依赖 NuGet 第三方运行库。Windows 开发环境可运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Configuration Release -WithDocs -PackageZip
```

构建脚本会执行禁用 API、框架引用程序集、输出文件、程序集引用、图标和 manifest 等检查。首次构建若系统没有 .NET Framework 4.0 引用程序集，脚本会下载项目所需的 Microsoft 参考程序集到 `.toolchain/`；该目录不会提交到仓库。

运行自动化测试：

```powershell
.\build\Tests\MQNetScan.Tests.exe
```

## 设备识别说明

当前版本优先使用端口和默认网关等线索：Windows 电脑、安卓设备、打印机、电子秤和服务器类别会显示识别依据与可信度；80/443 仅作为“路由器 / 网络设备”的低可信线索，默认网关身份仍应以网关配置确认。iPhone/iPad、电视、空调等设备没有统一的公开端口，本版本尚未实现 SSDP/mDNS 主动发现，不能承诺自动识别这些设备。后续可通过 SSDP、mDNS 和厂商协议继续扩展。识别结果始终是网络线索，不应替代人工确认。
